01 / OVERVIEW

기록의 시작을 더 가볍게.

하루 시그널은 사진과 위치 정보를 기반으로 일기 초안을 생성하고, 사용자가 내용을 편집해 기록과 감정의 흐름을 관리하는 서비스입니다. React 기반 프론트엔드 구현과 API 연동을 담당했습니다.

05 / TROUBLESHOOTING

AI 초안이 끝까지 도달하지 않던
연쇄 장애를 해결했습니다.

사진 업로드부터 키워드 생성, 일기 초안 생성, DB 저장까지 이어져야 하는 AI 초안 생성 흐름이 반복적으로 실패했습니다. 원인은 하나의 버그가 아니었습니다. 서비스마다 설정, 검증 로직, DB 스키마가 어긋나 있었고, 이 문제들이 서로 다른 지점에서 겹쳐 터졌습니다. 요청 흐름을 따라가며 실패 지점을 하나씩 분리해 해결했습니다.

  • 초안이 "diarySchema".diary 테이블에 정상 저장되는 것까지 확인

ROOT CAUSE → FIX 8 ISSUES

  1. 01
    photo-serviceExifUtils.java검증 과도
    PROBLEM

    촬영일이 “오늘과 정확히 같은 날짜”일 때만 통과시켜 정상 사진도 업로드에 실패했고, GPS 정보가 없으면 바로 실패했습니다.

    FIX

    촬영 시간 검증 기준을 완화했습니다.

  2. 02
    photo-serviceapplication.yml설정 불일치
    PROBLEM

    .env에는 KAKAO_REST_API_KEY가 있었지만 앱은 KAKAO_LOCAL_REST_API_KEY를 우선 읽어 위치 조회가 자주 실패했습니다.

    FIX

    Kakao API 키 alias를 반영했습니다.

  3. 03
    vision-aiai_client.py모델 입력 한계
    PROBLEM

    원본 이미지를 그대로 base64로 보내 LM Studio의 context size(4096)를 넘겨 400이 반환됐습니다. 재시도 루프가 실패 로그만 반복해 원인이 가려졌습니다.

    FIX

    이미지 리사이즈·압축 전처리를 추가했습니다.

  4. 04
    vision-aikeyword_repository.py스키마 불일치
    PROBLEM

    코드는 user_id 컬럼에 insert하려 했지만 실제 visionschema.user_keywords에는 해당 컬럼이 없어, 모델 분석이 성공해도 저장 단계에서 실패했습니다.

    FIX

    키워드 저장 쿼리를 실제 DB 스키마에 맞게 수정했습니다.

  5. 05
    diary-aidiary_ai_service.py검증 과도
    PROBLEM

    초안 길이와 키워드 규칙이 지나치게 엄격해 생성된 결과를 정상으로 인정하지 않았습니다.

    FIX

    초안 검증 기준을 완화했습니다.

  6. 06
    diary-aidiary.py스키마 불일치
    PROBLEM

    모델은 "diarySchema".diary를 바라봤지만 실제 테이블이 없어 저장 단계에서 UndefinedTable이 발생했습니다.

    FIX

    "diarySchema".diary 테이블을 생성했습니다.

  7. 07
    orchestra-serviceJobStatus.java스키마 불일치
    PROBLEM

    DB 체크 제약은 PENDING / COMPENSATING / FAILED인데 코드 enum은 WAIT / REWARDING / FAILURE여서 process_jobs insert/update 때 제약 위반이 발생했습니다.

    FIX

    상태값과 DB 제약의 정합성을 맞췄습니다.

  8. 08
    runtimeport 8003프로세스 중복
    PROBLEM

    8003 포트에 이전 Vision AI 프로세스가 남아 있어, 실행 중인 서비스와 수정한 코드가 서로 달라 패치가 반영되지 않았습니다.

    FIX

    중복 프로세스를 정리해 재기동하고, orchestra-service가 패치된 Vision AI를 바라보도록 설정을 변경했습니다.

특정 서비스의 단일 버그가 아니라 과도한 검증 로직, 외부 모델의 입력 한계, DB 스키마 불일치, 프로세스 중복이 동시에 얽힌 연쇄 장애였습니다.

VERIFIED

  • photo-service 업로드 성공
  • 패치된 Vision AI에서 키워드 7개 추출
  • diary-ai 초안 생성 및 DB 저장
  • POST /api/diary/create 성공 응답

PREVENTION

  • 서비스별 DB 스키마와 코드 enum·컬럼 문서화
  • 서비스 간 환경변수 이름 통일
  • Vision 입력 이미지 크기 제한 사전 적용
  • 초안·키워드 검증 기준을 모델 특성에 맞게 조정
  • 테스트·실행 포트별 프로세스 관리 기준 정리
  • E2E 통합 테스트 추가
